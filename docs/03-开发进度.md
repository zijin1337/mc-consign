## 2026-09-05 · 全面审查与加固

三条线并行审查（安全、交易逻辑、前端与数据模型）后按优先级修复：

1. **状态机原子化**：意向单的开始、完成、取消、撤回、售后处理、分派全部改成事务内 `select ... for update` 锁行并重校验状态，冲突方收到「状态已变化」而不是重复执行。买家撤回与中介开始撞车不再把商品卡在「交易中」。商品的审核、下架、删除也改成带状态条件的更新。超管不能推进自己是买卖方的单；驳回的售后不再能同时判卖家责任；被封禁的买家不能开始交易；已封禁的一方成交时不加信用分。新增取消原因 `buyer_withdrawn`（买家主动撤回，不算爽约）与 `listing_unavailable`（系统自动关闭）。
2. **开放重定向**：回跳地址改为 URL 解析后比对 origin，并拒绝反斜杠与空白，`/\evil.com` 一类被拦。
3. **统一限流** `src/lib/rate-limit.ts`（单机内存，接口可换 Redis）：登录按 IP 15 分钟 30 次、按账号 10 次且只计失败；验证码按 IP 每小时 20 条并加用途白名单，发送结果不再透露 QQ 是否已注册；注册与重置密码按 IP 每小时 10 次；Hypixel 拉取每人 10 分钟 20 次、刷新 5 次且只能刷新已收录玩家；皮肤接口只服务本站认识的 uuid 并按 IP 每分钟 120 次；下单每人 10 分钟 10 次。验证码校验改为原子计数、接受最近 3 条未用的码。
4. **跨对象联动** `src/lib/order-ops.ts`：删除、强制下架、卖家下架时关闭排队中的意向单并通知买家与中介；在售商品被编辑进入重审时通知排队方；封禁用户时下架其全部未售商品（含交易中）、关闭其作为买家的意向单并恢复商品在售、其作为中介的单退回待分派并通知超管改派；撤销中介资格同样改派。交易中取消时若卖家已被封，商品转为下架而不是回到在售。
5. **参数收敛与兜底** `src/lib/ids.ts`：所有路由 id、页码、筛选数值严格解析，乱值当作 404 或第一页，不再进 SQL 触发 500；Hypixel 面板加独立错误边界，缓存摘要带版本号，旧结构自动重抓；皮肤纹理区分「确实没有」与「上游抖动」，后者不缓存也不让浏览器缓存，纹理地址限定 Mojang 域名并限 2MB。
6. **打包修复**：上架上限与信用门槛在重新上架、被拒重提时同样检查；买家留言过违禁词；正版 ID 按 Minecraft 规则校验格式；上传按真实格式识别并限制像素总量；日期格式与质保日期固定用 `SITE_TZ`（默认上海）不受服务器时区影响；街机胜场只加各模式总量；特殊身份只算「部分核对」不打一致标；整数字段加上界；配置写入进事务；全数字用户名也能登录；生产启动自检 `src/instrumentation.ts` 拒绝弱密钥；种子脚本在生产拒绝默认口令、演示脚本拒绝运行；会话与验证码过期记录顺手清理；数据库加 CHECK 约束与「一商品只成交一次」唯一索引；公开列表只带模板标了 `publicInList` 的属性；中介可回看非在售商品；浏览量改用 `after()` 在响应后写入；详情查询用 `cache` 合并；补 `global-error.tsx`；表单单选多选组不再嵌套 label，首页筛选控件有可访问名，卡片不再用 aria-label 盖住内容，灰阶文字抬亮。

## 2026-09-05 · 求购功能

反向的信息流：之前只有卖家挂号、买家挑，现在买家也能挂「我想买什么」，卖家和中介把合适的账号推过去。施工契约在 `.local/wanted/spec.md`（工作目录不入库）：底层（schema、查询、Server Action、标签、通知、审计、配置、清理脚本）先由主会话落好，页面分买家与公开页 / 中介台与后台联动 / 测试与文档三个模块并行。

### 产品定义

- **求购单**：买家发布想要的账号条件（会员类型多选、最低等级、披风多选）、预算（上限必填、下限可选）、其他要求（300 字内）、可指定中介、有效期 7 / 14 / 30 / 60 / 90 天。**任何登录用户都能发，发布即公开、不经审核**；发布时拦违禁词与联系方式。标题由条件自动生成（`renderWantedTitle`，如「MVP+/MVP++ · 100 级以上 · 官方披风 · 预算 ¥3,000～¥5,000」），买家不写标题。
- **求购大厅** `/wanted` 对游客公开（同账号市场），按会员类型、预算上限筛选，24 条一页；**详情** `/wanted/[id]` 需登录（同账号详情）。买家用户名一律 `maskUsername`，任何地方不出现 QQ / 手机。
- **推荐**：账号的卖家可把自己在售 / 交易中的账号推荐给求购单；中介 / 超管可推荐市场上任何在售账号（不能是买家自己的）。同一账号对同一求购单只有一条记录：待回应 / 已采纳 / 已谢绝时不能再推，撤回后可再推（更新原记录）。留言 200 字内，同样过两道闸。
- **成交闭环**：买家在详情页对推荐点「去下单」，进入现有下单页 `/listings/{listingId}/buy?wanted={requestId}`；下单成功该推荐变「已采纳」、意向单挂 `orders.wanted_request_id`；意向单**完成** → 求购单「已完成」，其余待回应推荐关闭并通知推荐人。取消意向单不改求购单。
- **有效期**：到期后不再公开、不能被推荐，展示为「已过期」（库里仍是 open，查询时比较，不用定时任务）；买家可「续期」（从现在起加默认天数）、可「关闭」；编辑不改有效期。
- **管理**：超管可下架（填原因，买家收通知，待回应推荐关闭）/ 恢复；下架的求购只有买家本人与管理员 / 中介能打开，其他人 404。

### 数据模型

- `wanted_requests` 求购单：buyer_id、game_id、title、ranks（jsonb 数组，空 = 不限）、min_level、capes（jsonb 数组）、budget_min、budget_max、requirements、preferred_agent_id、status（`open / fulfilled / closed / removed`）、expires_at、admin_note、removed_by、view_count、closed_at。check 约束 `budget_max > 0`、`budget_min is null or budget_min <= budget_max`；索引 `(status, expires_at, created_at desc)`、`buyer_id`。
- `wanted_offers` 推荐：request_id（级联删除）、listing_id、seller_id（账号的卖家，推荐人是中介时也记）、offered_by（推荐人）、message、status（`pending / accepted / declined / withdrawn / closed`）、responded_at。唯一索引 `(request_id, listing_id)` 保证一账号一求购只一条；索引 listing_id、offered_by、`(request_id, status)`。
- `orders.wanted_request_id` 可空外键，部分索引 `where wanted_request_id is not null`。
- 迁移 `drizzle/0006_wanted.sql`。数据模型文档已同步（`02-数据模型初稿.md`）。
- 共享纯函数在 `src/lib/wanted-shared.ts`（预算文案、条件标签、标题、到期 / 展示状态 / 剩余天数、推荐是否可采纳），查询在 `src/lib/wanted.ts`（server-only），Server Action 在 `src/actions/wanted.ts`。

### 页面与入口

### 状态机

- 求购单：`open` → `fulfilled`（挂在它下面的意向单完成）/ `closed`（买家关闭）/ `removed`（超管下架）；`removed` → `open`（超管恢复）。`open` 且 `expires_at <= now()` 展示为「已过期」，续期回到求购中；关闭 / 完成 / 下架都不能再编辑。
- 推荐：`pending` → `accepted`（买家据此下单）/ `declined`（买家谢绝，之后该账号不能再推）/ `withdrawn`（推荐人或卖家撤回，可再推）/ `closed`（求购单完成 / 关闭 / 下架时批量关闭）。展示时若账号已不是在售 / 交易中，另加中性徽章「账号已不可购买」，「去下单」按钮只对 `isOfferActionable` 的推荐显示。

### 通知与留痕

- 新增通知类型：`wanted_new`（有买家指定你跟进求购，发给被指定中介）、`wanted_offer`（有人给你的求购推荐了账号；中介推荐别人的账号时卖家也收一条）、`wanted_offer_accepted`（买家采纳了你的推荐）、`wanted_offer_declined`（买家谢绝了你的推荐）、`wanted_closed`（买家关闭求购，发给待回应推荐的推荐人）、`wanted_fulfilled`（求购已通过其他账号成交，发给被关闭推荐的推荐人）、`wanted_removed`（求购被下架，发给买家与待回应推荐的推荐人）。全部站内 + QQ 邮箱抄送，走通用通知列表，不用改页面。
- 审计：`wanted_remove` / `wanted_restore`，targetType `wanted`。

### 限流与两道闸

- 发布 5 次 / 小时、续期 6 次 / 小时、推荐 20 次 / 小时（按用户，进程内存）；同时挂的求购单不超过 `wanted_max_active`。
- 其他要求与推荐留言先过违禁词库，再过联系方式检测 `src/lib/contact-leak.ts`：QQ / 扣扣 / 企鹅、微信 / vx / wx、Telegram / Discord 等外部聊天工具、外链、手机号、7 位以上连续数字（预算、等级、年份到不了 7 位，「3000-5000」这类区间不会误伤；全角数字先 NFKC 归一化）。错误落在 `errors.requirements` / `errors.message`，表单提示用 `CONTACT_LEAK_HINT`。

- **构图**：相机拉远到 128（fov 30），目标点在角色与传送门之间，角色在画面左三分之一、门框在右侧完整入画；灯笼移到右前角。角色改为背身走向斜放的门框（yaw 2.27），头只侧转 0.6 rad——镜头几乎在正后方，回头太多只会露出后脑。
- **角色**：skinview3d 的硬板披风关掉（`backEquipment = null`），换成 10×16 分段平面的布料披风，顶点着色器里做旗帜式摆动（越靠下摆幅越大，向画面右侧飘并向后掀），位移同时注入 `customDepthMaterial`，影子跟着动；右手挂一把钻石剑——16×16 像素图逐格挤成 1 单位体素的 `InstancedMesh`，柄移到原点后转成刃朝前下的持握姿态。姿态每帧写入：右臂前抬、左臂后摆、双腿迈步、轻微呼吸。
- **环境**：浮岛用苔石（Voronoi 石缝 + 值噪声苔斑）、圆石、深板岩、磨制深板岩四种程序化纹理拼成不规则一片，中间两列磨制深板岩是通向门的路，下面收窄两层，几丛草（十字面片、alphaTest）；远处三座暗岛、五块缓慢起伏自转的碎块、一张深蓝到底色的天幕；线性雾 120～420。
- **光**：半球光 + 冷色平行主光（2048 阴影）+ 传送门紫色点光 2200 + 灯笼暖光 380 + 镜头侧一点青色补光；skinview3d 的相机光关掉。
- **粒子**：三组 `Points` + 自写着色器（寿命循环、上升、正弦漂移、柔光贴图、加色混合）：传送门碎光 140、灯笼火星 26、空气灰尘 90。
- **传送门**：像素化双层流动噪声加轻微旋涡与更亮的中心，配 Bloom 真正发光；alpha 0.72、门后光晕 0.4，避免烧成白。
- 纹理与钻石剑像素图搬到 `stage-textures.ts`；`stage-scene.ts` 只管场景组装与动画。海报与人偶封面已用新场景重新导出。
- 顺手修了 eslint 配置：`.next-prodtest/**` 之前没在忽略列表里，跑过一次生产构建后 `pnpm lint` 会扫进几千条生成代码的告警。

### 方块材质换成第三方 CC0 像素材质（同日）

用户问「环境等方块可以用我的世界原版纹理吗」。原版贴图是 Mojang 的版权素材，其使用准则不允许用在商业服务上，这个站又是收费中介，所以给了三条路（继续程序化 / 许可宽松的第三方材质 / 原版），用户选了第三方。

- 选用 OpenGameArt「16x16 Block Texture Set」（作者 Kutejnikov，CC0，可商用无需署名），取 slate（代深板岩）、slate_tiles（代磨制深板岩）、cobblestone、cobblestone_mossy、grass_top、obsidian 六种方块与 grass_tall / grass3 / fern 三种草，放在 `public/stage/textures/`，同目录 `LICENSE.txt` 记来源与许可。对比过的还有同站 CC0「Assorted Minecraft style textures」（Minetest 风格命名，含黑曜石与火把）和 Minetest Game 默认材质（CC BY-SA 3.0，需署名），前者风格杂、后者要署名，都没用。Kenney Voxel Pack 虽是 CC0 但是 128px 矢量风，不是像素画。
- 代码：`stage-textures.ts` 新增 `loadStageTextures()`，按 `TEXTURE_FILES` 表用 `TextureLoader` 加载（NearestFilter、不生成 mipmap），缺文件或加载失败时该项退回程序化纹理；`buildHeroStage` / `buildCardStage` 因此变成 async，`hero-stage.tsx`、`stage-renderer.ts`、实验室页同步改为 await。草顶与草丛用材质 color 压暗压灰（#8a9a82 / #a8b3a0），保持展厅的低饱和；16×32 的高草面片按比例拉高。灯笼、粒子、天幕、传送门、角色皮肤与披风仍是自绘。
- 依旧不含任何 Mojang 原版贴图；真皮肤是玩家自己的内容，从 Mojang 接口按需取，与此无关。

### 传送门改成「快把人吸进去」的旋涡（同日）

用户要传送门「虚幻一些、快把人吸进去的效果」。四层一起做：

- **门面着色器**：从平铺的流动噪声改成向心螺旋——角度随半径的对数旋转、半径随时间向内收，叠一层涌向中心的细条与高斯亮核（uCore 近白紫），像素化细到 48×72 格，边缘柔化。
- **门外能量漏斗**：门框前一张 84×104 的加色面片，极坐标里一圈圈向门心涌的射线，只画门框之外、越远越淡，能量像从门里溢出把周围往里卷。
- **被吸的东西**：220 颗粒子在门前方的锥体里绕门轴旋进门心（越近越快、越亮、越大，`suctionParticles`）；四块碎块沿同样的螺旋飞进门心，越近越小转得越快，到门心消失再从远处出现；角色身体前倾 0.1 rad，披风掀得更高、加一层 5Hz 的快抖；门光按 2.3Hz 呼吸并带一点闪烁。
- **屏幕空间旋涡**（`stage-post.ts` 调色 pass 里）：每帧把门心投影到屏幕 uv，以门心为轴按距离衰减地旋转采样坐标（最大 0.28 rad）并轻微向门心拉拽，门框直边、地面、角色靠门一侧的轮廓都被卷向门心；相机拖动时门心跟着重新投影。静态海报在相机就位后再落一次钩子，门心位置才正确。
- 这些都只在场景代码里，不影响页面结构；e2e 契约不变，未重跑整套。
